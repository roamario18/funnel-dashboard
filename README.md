# Дашборд воронки продаж

Приложение показывает аналитику сделок CRM текущего пользователя внутри Битрикс24.

**Портал:** `https://bs18.bitrix24.ru` → левое меню **«Дашборд воронки продаж»** / **«Воронка продаж»**.  
**Контейнер (только из меню):** [https://app-b7ba428c3bbc.vibecode.bitrix24.tech](https://app-b7ba428c3bbc.vibecode.bitrix24.tech)  
**Исходники:** [https://github.com/перroamario18/funnel-dashboard](https://github.com/roamario18/funnel-dashboard)

Прямая ссылка Black Hole даёт 401 (`OWNER_ONLY`) — открывать из меню, не по URL `app-…`.

## Сценарии

- Сводка по стадиям выбранной воронки: количество и сумма в рублях (`stageId`).
- Выбор воронки CRM (основная и дополнительные).
- KPI: сумма открытых сделок и средний чек в рублях (два знака после запятой), число выигранных за период — целое.
- Последние 20 сделок: название, сумма в валюте сделки, стадия, ответственный.
- Фильтр по дате создания: 7 дней / 30 дней / все время. Сделки за сегодня входят в 7 и 30 дней.
- Открытие из левого меню (placement отдаёт `code` без `state`) ставит сессию само, без ошибки `invalid_state`.

Работает от лица вошедшего сотрудника (`vibe_app_` + сессия). Ключ и вызовы Vibe API только на сервере (BFF). Секреты в `.env`, не в git.

## Скоупы

Боевой ключ приложения (`vibe_app_`) — только данные и встройка:


| Скоуп       | Зачем                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------- |
| `crm`       | Сделки, стадии, поиск                                                                          |
| `user`      | ФИО ответственного                                                                             |
| `placement` | Пункт левого меню портала                                                                      |
| `entity`    | Остался с выпуска ключа (тогда набор прав был широким). Дашборд хранилище `entity` не вызывает |


Платформенных `vibe:*` на боевом ключе нет. Режим `READONLY`. Актуальный `GET /v1/me` без секрета — [docs/me.json](docs/me.json).   

Ответ по замечаниям — [docs/remarks-checklist.md](docs/remarks-checklist.md).

## Ограничения

- Доступ: пункт левого меню виден сотрудникам портала `bs18.bitrix24.ru`. Учётка для проверки передаётся в переписке по тикету.
- Суммы открытых, средний чек и стадии считаются в рублях: иностранные валюты пересчитываются по курсу из CRM (`GET /v1/currencies`). Курс портала, не биржи. В таблице последних сделок сумма остаётся в валюте сделки. Если валют несколько — предупреждение с использованным курсом; если курса в CRM нет — сумма входит в KPI без пересчёта, тоже с предупреждением.
- Выборка ограничена 5000 сделками; при обрезке показывается предупреждение.
- Сессия `vibe_app_` живёт 24 часа, без автопродления.
- Пустая выборка — empty-state, не ошибка.
- Поштучный запрос пользователей — только при сбое сети / 5xx; на 401/403 в таблице остаётся `ID`.



## Как проверить

1. Левое меню **«Воронка продаж»** — должен открыться дашборд, не `invalid_state`.
2. Фильтр 7 / 30 дней — сделки, созданные сегодня, в списке; KPI и стадии пересчитываются.
3. Смешение валют — KPI и стадии в ₽ с копейками, в таблице исходная валюта, над таблицей предупреждение с курсом CRM.
4. Сотрудник без CRM должен увидеть понятную ошибку прав, а не stack trace. Скрин: [docs/screenshots/нет-доступа-CRM.jpg](docs/screenshots/нет-доступа-CRM.jpg).
