# Дашборд воронки продаж

Приложение показывает аналитику сделок CRM текущего пользователя внутри Битрикс24.

## Сценарии

- Сводка по стадиям выбранной воронки: количество и сумма (`stageId`).
- Выбор воронки CRM (основная и дополнительные).
- KPI: сумма открытых сделок, число выигранных за период, средний чек.
- Последние 20 сделок: название, сумма, стадия, ответственный.
- Фильтр по дате создания: 7 дней / 30 дней / все время.

Работает от лица вошедшего сотрудника (`vibe_app_` + сессия). Ключ и вызовы Vibe API только на сервере (BFF). Секреты в `.env`, не в git.

## Скоупы

Боевой ключ приложения (`vibe_app_`) — только данные и встройка:

| Скоуп | Зачем |
|---|---|
| `crm` | Сделки, стадии, поиск |
| `user` | ФИО ответственного |
| `placement` | Пункт левого меню портала |
| `entity` | Остался с выпуска ключа (тогда набор прав был широким). Дашборд хранилище `entity` не вызывает |

Платформенных `vibe:*` на боевом ключе нет. Режим **`READONLY`**. Актуальный `GET /v1/me` без секрета — [docs/me.json](docs/me.json).

## Ограничения

- Доступ: пункт левого меню виден сотрудникам портала `bs18.bitrix24.ru`. Прямой URL Black Hole закрыт политикой `OWNER_ONLY` — открывать из меню, не по ссылке `app-…`. Проверяющему: скриншоты трёх состояний в `docs/screenshots/` либо учётка на демо-портале по запросу в обращении.
- Суммы открытых, средний чек и стадии считаются в рублях: иностранные валюты пересчитываются по курсу из CRM (`GET /v1/currencies`). В таблице последних сделок сумма остаётся в валюте сделки.
- Агрегация ограничена 5000 записями; при обрезке показывается предупреждение.
- Сессия `vibe_app_` живёт 24 часа, без автопродления.
- Пустая выборка — empty-state, не ошибка.
- Поштучный запрос пользователей — только при сетевом сбое / 5xx; на 401/403 в таблице остаётся `ID`.

## Как проверить

1. Левое меню **«Воронка продаж»** / **«Дашборд воронки продаж»**. Живой адрес сервера: https://app-b7ba428c3bbc.vibecode.bitrix24.tech (из меню, не напрямую).
2. Сменить фильтр 7 / 30 / все — таблицы и KPI пересчитываются.
3. Сотрудник без CRM должен увидеть понятную ошибку прав, а не stack trace.
